Overview

The Gopher Social Network backend uses a RESTful API design style, built with Go and the Chi Router framework.

Basic Information

Base URL http://localhost:8080
Data Format JSON (Content-Type: application/json)
Authentication JWT Bearer Token
Request Timeout 60 seconds
Rate Limiting Max 20 requests per IP within 5 seconds (configurable)

Authenticated Request Format

Authorization: Bearer <jwt_token>

Pagination Parameters

Parameter Type Default Description
limit int 20 Items per page (1-20)
offset int 0 Offset
sort string desc Sort order (asc/desc)

Authentication API

Handles user registration, login, account activation, and password reset.

POST /auth/register Public

Register a new user account. The system will send an activation email.

Request Body

Field Type Required Description
username string Yes Username, unique
email string Yes Email address, unique
password string Yes Password

Request Example

{
    "username": "newuser",
    "email": "user@example.com",
    "password": "securepassword123"
}

Response

// 201 Created
{
    "message": "registration successful, please check your email to activate your account"
}
POST /auth/token Public

User login, verifies credentials and returns a JWT token.

Request Body

Field Type Required Description
email string Yes Registered email
password string Yes Password

Response

// 201 Created
{
    "token": "eyJhbGciOiJIUzI1NiIs..."
}
JWT Token Claims:
  • sub: User ID
  • exp: Expiration time (default 72 hours)
  • iat: Issued at time
  • iss: Issuer
  • ver: Token version number (used to invalidate old tokens)
POST /auth/activate/{token} Public

Activate user account via the activation link sent by email.

Path Parameters

Parameter Type Description
token string Activation token (SHA256 hash stored)

Response

// 200 OK
{
    "message": "account activated successfully"
}
POST /auth/forgot-password Public

Send a password reset email.

Request Body

Field Type Required Description
email string Yes Registered email

Response

// 200 OK
{
    "message": "password reset email sent"
}
POST /auth/reset-password Public

Reset password using a token.

Request Body

Field Type Required Description
token string Yes Password reset token
password string Yes New password

Response

// 200 OK
{
    "message": "password reset successfully"
}

POST /posts Auth Required

Create a new post.

Request Body

Field Type Required Description
title string Yes Post title
content string Yes Post content
tags string[] No Tag array

Response

// 201 Created
{
    "id": 1,
    "title": "New Post",
    "content": "...",
    "tags": ["golang"],
    "created_at": "2026-01-01T00:00:00Z",
    "updated_at": "2026-01-01T00:00:00Z"
}
PATCH /posts/{postId} Auth Required

Update a post (only the author or moderator can perform this action). Uses optimistic locking (version field) to prevent concurrent conflicts.

Request Body

Field Type Required Description
title string No New title
content string No New content
tags string[] No New tags
version int Yes Current version number
Optimistic Locking Mechanism: The current version must be provided when updating. The database checks if the version matches. If it doesn't match, a 404 is returned, indicating the post was modified by someone else.
DELETE /posts/{postId} Auth Required

Delete a post (only the author or admin can perform this action).

PUT /posts/{postId}/like Auth Required

Like a post (idempotent operation, repeated likes have no effect).

DELETE /posts/{postId}/like Auth Required

Unlike a post.

Field Type Required Description

Get a list of comments liked by the current user.

Admin API

Admin-only endpoints, require admin role permissions.

PATCH /admin/users/{username}/ban Admin

Ban a user. Banned users will be unable to log in.

Path Parameters

Parameter Type Description
username string Username to ban

Response

// 204 No Content
Side Effect: The system will send a ban notification email to the banned user.
PATCH /admin/users/{username}/unban Admin

Unban a user.

Response

// 204 No Content
Side Effect: The system will send an unban notification email to the unbanned user.

Middleware

Middleware chain in the request processing flow.

Request Processing Flow

CORS → Recoverer → RequestID → ClientIP → Logger → Timeout → RateLimiter → Handler

Middleware Descriptions

Middleware Description
CORS Handles cross-origin requests, allows frontend to access the API
Recoverer Catches panics and returns 500 errors, prevents server crashes
RequestID Generates a unique ID for each request, aids in tracking
ClientIP Extracts the client IP address
Logger Logs request details (method, path, status code, duration)
Timeout Sets request timeout (60 seconds)
RateLimiter IP-based rate limiting (optional, depends on Redis)
AuthTokenMiddleware Validates JWT token and injects user info into context
postsContextMiddleware Loads post into context
commentsContextMiddleware Loads comment into context
checkPostOwnerShip Verifies user is the post owner or has the required role
checkCommentOwnerShip Verifies user is the comment owner or has the required role
verifyAdminPermMiddleware Verifies user has admin permissions

Role Permission Hierarchy

Role Level Permission Description
user 1 Regular user, can manage their own content
moderator 2 Moderator, can edit/delete any posts and comments
admin 3 Admin, can ban/unban users

Error Handling

Unified error response format.

Error Response Format

{
    "error": {
        "type": "error_type",
        "message": "Error description message"
    }
}

Error Types

Type HTTP Status Code Description
bad_request 400 Malformed request
unauthorized 401 Not authenticated or authentication failed
forbidden 403 No permission to perform this action
not_found 404 Resource does not exist
conflict 409 Resource conflict (e.g., email already exists)
validation_error 422 Request validation failed
rate_limit_exceeded 429 Too many requests
internal_server_error 500 Internal server error

Error Response Examples

// 401 Unauthorized
{
    "error": {
        "type": "unauthorized",
        "message": "invalid or expired token"
    }
}

// 409 Conflict
{
    "error": {
        "type": "conflict",
        "message": "a user with that email already exists"
    }
}

// 429 Rate Limit
{
    "error": {
        "type": "rate_limit_exceeded",
        "message": "rate limit exceeded, retry after 5s"
    }
}
