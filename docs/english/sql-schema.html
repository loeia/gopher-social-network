Overview

Gopher Social Network uses PostgreSQL 16 as the primary database and Redis as the caching layer.

Database Information

Database Type PostgreSQL 16.3
Default Database Name gopher-social-network
Default User admin
Connection Pool Config Max connections: 30, Idle connections: 30, Idle timeout: 15m

ER Diagram

The entity-relationship diagram shows the relationships between tables.

Relationship Descriptions

  • Many-to-One users.role_id → roles.id: Each user has one role
  • One-to-Many posts.user_id → users.id: Each user can create multiple posts
  • One-to-Many comments.post_id → posts.id: Each post can have multiple comments
  • One-to-Many comments.user_id → users.id: Each user can create multiple comments
  • Self-Referencing comments.parent_id → comments.id: Comments support multi-level replies
  • One-to-Many comments.reply_to_user_id → users.id: Reply target user
  • Many-to-Many followers: Follow relationships between users (self-referencing)
  • Many-to-Many post_likes: User likes on posts
  • Many-to-Many comment_likes: User likes on comments

Table Details

roles Main

Roles table, defines user roles and permission levels in the system.

Column Type Constraints Description
id SERIAL PRIMARY KEY Role ID
name VARCHAR(255) UNIQUE NOT NULL Role name (user/moderator/admin)
description VARCHAR(255) Role description
level INTEGER NOT NULL Permission level (1=user, 2=moderator, 3=admin)

Default Data

INSERT INTO roles (name, description, level) VALUES
    ('user', 'Regular user', 1),
    ('moderator', 'Moderator', 2),
    ('admin', 'Administrator', 3);
users Main

Users table, stores all user information.

Column Type Constraints Description
id BIGSERIAL PRIMARY KEY User ID
username VARCHAR(255) UNIQUE NOT NULL Username
email VARCHAR(255) UNIQUE NOT NULL Email address
password VARCHAR(255) NOT NULL Password hash (bcrypt)
created_at TIMESTAMPTZ DEFAULT NOW() Creation timestamp
is_active BOOLEAN DEFAULT FALSE Whether the user is activated
role_id INTEGER FOREIGN KEY → roles.id Role ID
token_ver INTEGER DEFAULT 0 Token version number (for invalidating old tokens)

avatar_mime VARCHAR(50) Avatar MIME type
bio TEXT User biography
links VARCHAR(255)[] DEFAULT '{}' Personal links array
show_email BOOLEAN DEFAULT FALSE Whether to display email publicly
is_banned BOOLEAN DEFAULT FALSE Whether the user is banned
followers_count BIGINT DEFAULT 0 Follower count (denormalized)
following_count BIGINT DEFAULT 0 Following count (denormalized)
posts_count BIGINT DEFAULT 0 Post count (denormalized)
likes_count BIGINT DEFAULT 0 Likes received count (denormalized)
replies_count BIGINT DEFAULT 0 Replies count (denormalized)
Design Note: Denormalized fields (followers_count, etc.) are used to store counts, avoiding frequent COUNT queries. Count consistency is maintained automatically via triggers.
posts Main

Posts table, stores user-published post content.

Column Type Constraints Description
id BIGSERIAL PRIMARY KEY Post ID
user_id BIGINT FOREIGN KEY → users.id NOT NULL Author ID
title VARCHAR(255) NOT NULL Post title
content TEXT NOT NULL Post content (supports Markdown)
tags VARCHAR(255)[] DEFAULT '{}' Tags array
version INTEGER DEFAULT 1 Optimistic lock version number
created_at TIMESTAMPTZ DEFAULT NOW() Creation timestamp
updated_at TIMESTAMPTZ DEFAULT NOW() Update timestamp
comment_count BIGINT DEFAULT 0 Comment count (denormalized)
like_count BIGINT DEFAULT 0 Like count (denormalized)
view_count BIGINT DEFAULT 0 View count

Optimistic Lock Update Example

-- Check version number when updating a post
UPDATE posts 
SET title = $1, content = $2, tags = $3, 
    updated_at = NOW(), version = version + 1 
WHERE id = $4 AND version = $5 
RETURNING version, updated_at;
comments Main

Comments table, supports a multi-level reply comment system.

Column Type Constraints Description
id BIGSERIAL PRIMARY KEY Comment ID
post_id BIGINT FOREIGN KEY → posts.id NOT NULL Parent post ID
user_id BIGINT FOREIGN KEY → users.id NOT NULL Comment author ID
content TEXT NOT NULL Comment content
parent_id BIGINT FOREIGN KEY → comments.id Parent comment ID (NULL for top-level comments)
reply_to_user_id BIGINT FOREIGN KEY → users.id Reply target user ID
created_at TIMESTAMPTZ DEFAULT NOW() Creation timestamp
like_count BIGINT DEFAULT 0 Like count (denormalized)
Multi-level Reply Design: A comment tree structure is implemented through parent_id self-referencing. Top-level comments have parent_id = NULL, while replies have parent_id pointing to the parent comment. Supports up to two levels of replies.
followers Junction

Follow relationships table, stores follow relationships between users.

Column Type Constraints Description
user_id BIGINT FOREIGN KEY → users.id NOT NULL Followed user ID
follower_id BIGINT FOREIGN KEY → users.id NOT NULL Follower user ID
created_at TIMESTAMPTZ DEFAULT NOW() Follow timestamp

Constraints

-- Composite unique constraint to prevent duplicate follows
UNIQUE (user_id, follower_id)

-- Check constraint to prevent self-following
CHECK (user_id != follower_id)

Post likes table.

Column Type Constraints Description

Comment likes table.

Column Type Constraints Description
comment_id BIGINT FOREIGN KEY → comments.id NOT NULL Comment ID
user_id BIGINT FOREIGN KEY → users.id NOT NULL User who liked the comment
created_at TIMESTAMPTZ DEFAULT NOW() Like timestamp

Constraints

-- Composite unique constraint

user_invitations Temporary

User activation invitations table, stores invitation tokens for unactivated users.

Column Type Constraints Description
user_id BIGINT FOREIGN KEY → users.id NOT NULL User ID
token VARCHAR(255) NOT NULL Activation token (SHA256 hash)
expiry TIMESTAMPTZ NOT NULL Expiry timestamp
Cleanup Policy: After user activation, the corresponding invitation record is deleted.
password_resets Temporary

Password resets table, stores password reset tokens.

Column Type Constraints Description
token VARCHAR(255) NOT NULL Reset token (SHA256 hash)
user_id BIGINT FOREIGN KEY → users.id NOT NULL User ID
expiry TIMESTAMPTZ NOT NULL Expiry timestamp (default 15 minutes)
Security Policy: After password reset, the corresponding record is deleted. Additionally, the user's token_ver is incremented to invalidate old tokens.

Triggers & Constraints

Database-level constraints and triggers for maintaining data consistency.

Trigger: Auto-update Post Like Count

-- Automatically update posts.like_count when inserting or deleting from post_likes
CREATE OR REPLACE FUNCTION update_post_like_count()
RETURNS TRIGGER AS $$
BEGIN
    IF TG_OP = 'INSERT' THEN
        UPDATE posts SET like_count = like_count + 1 WHERE id = NEW.post_id;
    ELSIF TG_OP = 'DELETE' THEN
        UPDATE posts SET like_count = like_count - 1 WHERE id = OLD.post_id;
    END IF;
    RETURN NULL;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER trigger_update_post_like_count
    AFTER INSERT OR DELETE ON post_likes
    FOR EACH ROW
    EXECUTE FUNCTION update_post_like_count();

Trigger: Auto-update Follow Counts

-- Automatically update users' followers_count and following_count when inserting or deleting from followers
CREATE OR REPLACE FUNCTION update_user_follow_counts()
RETURNS TRIGGER AS $$
BEGIN
    IF TG_OP = 'INSERT' THEN
        -- Increment followed user's follower count
        UPDATE users SET followers_count = followers_count + 1 WHERE id = NEW.user_id;
        -- Increment follower's following count
        UPDATE users SET following_count = following_count + 1 WHERE id = NEW.follower_id;
    ELSIF TG_OP = 'DELETE' THEN
        -- Decrement followed user's follower count
        UPDATE users SET followers_count = followers_count - 1 WHERE id = OLD.user_id;
        -- Decrement follower's following count
        UPDATE users SET following_count = following_count - 1 WHERE id = OLD.follower_id;
    END IF;
    RETURN NULL;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER trigger_update_user_follow_counts
    AFTER INSERT OR DELETE ON followers
    FOR EACH ROW
    EXECUTE FUNCTION update_user_follow_counts();

-- Automatically set updated_at to current time when updating posts
CREATE OR REPLACE FUNCTION update_updated_at_column()
RETURNS TRIGGER AS $$
BEGIN
    NEW.updated_at = NOW();
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;

Index Design

Indexes designed for improved query performance.

Users Table Indexes

idx_users_email (email) idx_users_username (username) idx_users_role_id (role_id) idx_users_is_active (is_active)

Posts Table Indexes

idx_posts_user_id (user_id) idx_posts_created_at (created_at DESC) idx_posts_tags (tags USING GIN) idx_posts_title_trgm (title gin_trgm_ops)

Comments Table Indexes

idx_comments_post_id (post_id) idx_comments_user_id (user_id) idx_comments_parent_id (parent_id) idx_comments_created_at (created_at)

Followers Table Indexes

idx_followers_user_id (user_id) idx_followers_follower_id (follower_id)

Post Likes Table Indexes

idx_post_likes_post_id (post_id) idx_post_likes_user_id (user_id)

Comment Likes Table Indexes

idx_comment_likes_comment_id (comment_id) idx_comment_likes_user_id (user_id)
GIN Index: The posts table's tags field uses a GIN (Generalized Inverted Index) index, supporting efficient array containment queries (@> operator).
pg_trgm Extension: The posts table's title field uses a GIN index with the pg_trgm extension, supporting efficient fuzzy search (ILIKE queries).

Cascade Actions

Action Description
CASCADE When deleting a parent record, automatically delete all associated child records
RESTRICT Prevent deletion of a parent record if associated child records exist
SET NULL When deleting a parent record, set the foreign key in child records to NULL
